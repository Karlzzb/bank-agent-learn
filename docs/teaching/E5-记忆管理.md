# E5 记忆管理

> 对应 git tag:`e5`(会话内摘要压缩 + 跨会话长期偏好;与 e4/e6 同 commit)
> 本集痛点:对话越聊越贵、越聊越糊涂;老客户隔天再来,客服又从头问起。
> 上一集:E4 会话持久化 | 下一集:E6 PII 脱敏

## 开场话术

上一集我们解决了"断线续聊":进程重启,会话还在。
但请先想清楚一件事:会话还在,不等于这个客服"有脑子"。
今天讲两个任何坐席团队都懂、却常被 AI 项目忘掉的常识。
第一个常识:通话内容不能无限长地往小本本上抄。
客户聊了四十轮,你把四十轮原话一字不落塞给大模型,token 账单随轮数线性上涨,聊得越久每一轮越贵。
更糟的是,模型会被自己的记性淹没:开头交代过的正事,聊到后面它反而"前说后忘",答非所问。
上下文窗口不是硬盘,塞得越满,脑子越乱。
人类客服怎么做?
交接班时写一页摘要:客户办了什么业务、结论是什么、还有什么没办完。
没有任何一家银行要求坐席把全天通话录音逐字誊一遍再交班。
第二个常识:好客服记得老客户。
客户上周说过"我常用 A002 账户,查余额就查它"。
这周他再来,新会话一开,AI 又客客气气地问:"请问您要查哪个账户?"
客户心里的 OS 是:我上周不是跟你说过了吗?
注意,这和上一集的断线续聊是两回事。
续聊,是同一个会话掉线之后接着聊。
今天要的是:隔天、隔周、换了一个全新会话,它还认得你这个人。
这两个常识,对应今天的两样东西:会话内的摘要压缩,和跨会话的长期记忆。
两样都有工业级的坑,我们一个一个看,看完直接上手演示。

## 概念要点

- **两层记忆,分开解**:会话内靠"摘要压缩"控制上下文体积,跨会话靠"长期偏好"记住老客户。
  两件事机制完全不同,入口也不同,不要混为一谈(均在 `src/bank_agent/memory/nodes.py`)。
- **摘要压缩的刀法**:消息数超 `HISTORY_MAX_MESSAGES`(默认 12)时,最旧一段交给 LLM 压缩成一段中文摘要。
  摘要原位替换最早一条消息——位置不变、顺序不变,LLM 看到的对话流向是对的;只保留最近 `HISTORY_KEEP_RECENT`(默认 4)条原文。
  切口严格对齐到 HumanMessage 边界,绝不把 AIMessage(tool_calls) 和它的 ToolMessage 拦腰斩断——斩断了,模型会看到一次"没有下文的工具调用",直接懵掉。
  找不到安全切口就本轮不压缩,等下一轮,宁可超一轮也不乱切(`manage_context`,`src/bank_agent/memory/nodes.py`;阈值在 `.env` 里调,不改代码)。
- **触发词门控,零成本穿透**:用户消息含"记住/常用/默认/以后/偏好"任一触发词,才调一次 LLM 提取偏好。
  其余每一轮原样穿透,不多花一个 token——长期记忆不该给每句话都加税(`MEMORY_TRIGGER_WORDS` 与 `save_memory`,`src/bank_agent/memory/nodes.py`)。
- **长期记忆落哪**:自研 SqliteStore 实现 LangGraph 的 BaseStore 接口,只实现 batch/abatch 两个抽象方法,其余由基类派生。
  单文件 `memory.sqlite3`,命名空间 `("profiles", customer_id)` 按客户隔离——张三的偏好,李四的会话永远读不到(`src/bank_agent/memory/store.py`)。
- **偏好注入的位置有讲究**:不在 Coordinator 注入——它只分派不办事,看了偏好也用不上,白白占上下文。
  由父图的领域 runner 在调子图前 `load_preferences` → `format_preferences`,渲染成一行 system 文本,经子图私有键 `memory_context` 注入。
  谁办事,谁才需要知道客户的偏好(`src/bank_agent/graph/builder.py`、`src/bank_agent/graph/subgraphs.py`)。
- **与 PII 的交接点(本集必须讲)**:`save_memory` 拿到的输入是已脱敏文本。
  若提取结果里含 `[PHONE_1]` 这类占位符,整条丢弃(`contains_placeholder`,`src/bank_agent/pii.py`)。
  道理很硬:占位符只是本会话的临时映射标记,落进跨会话 store 既无意义也无法回填——所以 store 永不落 PII。
  提取输出复用 `src/bank_agent/json_output.py` 的工业级 JSON 解析;解析失败记 warning 跳过,绝不为一条偏好炸掉整个会话。

## 演示步骤

1. 检出本集 tag 并起栈(终端一,全程保持运行):
   ```bash
   git checkout e5
   make run    # 种子数据 + 3 个 MCP Server + API
   ```
   预期:输出"已启动:3 个 MCP Server + API(Ctrl+C 全部停止)"。
2. 先验证"零成本设计"(终端二):
   ```bash
   make cli
   ```
   预期:打印"银行客服已就绪(客户 C001)。输入 quit 退出。"
   输入一句**不含任何触发词**的普通业务话:`帮我查一下余额`,正常作答后 `quit`。
   然后查记忆库:
   ```bash
   sqlite3 -readonly memory.sqlite3 ".tables"
   sqlite3 -readonly memory.sqlite3 "SELECT COUNT(*) FROM store;"
   ```
   预期:表 `store` 存在(CLI 启动时建表),但行数是 0。
   (镜头:指着那个 0——"没有触发词的轮次,不提取、不落库,一个 token 都没多花。")
3. 教它记住老客户(终端二):
   ```bash
   make cli
   ```
   输入:`记住我以后默认用 A002 账户,查余额就查它`,得到确认后 `quit`。
   再看记忆库:
   ```bash
   sqlite3 -readonly memory.sqlite3 "SELECT namespace, key, value FROM store;"
   ```
   预期:多出一行,namespace 是 `profiles.C001`,value 是含 `A002` 的 JSON。
   (讲解:key 名由 LLM 现场命名,可能是"默认账户"也可能是"常用账户",不必逐字;namespace 里的 C001 才是重点——偏好按客户隔离。)
4. 换一个全新会话验证(终端二,注意**不带** thread_id,代表"隔天再来"):
   ```bash
   make cli
   ```
   输入:`帮我查一下余额`。
   预期:它不再追问"查哪个账户",直接按 A002 作答。
   (镜头:把第 2 步同一个问题的"从头问起",和这一次的"直接就办"剪在一起——对比本身就是全部论据;上一集存的是会话,这一集存的是人。)
5. 会话内摘要压缩(终端二)。
   把阈值调小再起 CLI,让压缩在长对话前就触发。
   注意:e5 时代日志还没接控制台(那是 E7 可观测性要补的课),这里临时给终端装上"日志眼镜":
   ```bash
   HISTORY_MAX_MESSAGES=6 .venv/bin/python -c "import asyncio, logging; logging.basicConfig(level=logging.INFO); from bank_agent.cli import main; asyncio.run(main())"
   ```
   在同一终端连聊四五轮:寒暄、查余额、查明细,随意组合。
   预期:消息数一过阈值,终端滚出日志"会话消息数 N 超阈值 6,最旧 K 条压缩为摘要"(logger `bank_agent.memory.nodes`)。
   再追问:`我们刚才都聊了哪些事?`
   预期:答复仍能覆盖最早的话题——原文已被修剪,是摘要在替它记事。
   (讲解:摘要的具体措辞随模型而定,不必背稿;必然发生的是两条工业指标——旧话不丢、消息总数有界。)
6. 确定性回归,零 API 消耗:
   ```bash
   make test
   ```
   预期:全绿。
   点名 `tests/test_memory.py`:进程重启续聊、长会话摘要压缩、跨会话偏好生效、含占位符的提取结果被丢弃、无触发词零额外调用、命名空间按客户隔离。
   全部用脚本化假模型跑,不碰真实 LLM,不花一分钱 API。
7. 演示结束回到主线:
   ```bash
   git checkout main
   ```

## 收尾钩子

今天补齐了两层记忆。
会话内:消息数超阈值就写"交接班摘要",切口对齐消息边界,成本和注意力同时有界。
跨会话:触发词门控的偏好提取,落到按客户隔离的 SQLite store,老客户进门直接被认出来。
外加一道刚才没怎么展开的保险:记忆库的输入全程是脱敏文本,含占位符的提取结果一律丢弃,`memory.sqlite3` 里永远不会有真手机号。
等等——脱敏?占位符?这两个词里藏着一整集的内容。
镜头一转:客户报给客服的手机号、身份证号,此刻正躺在发往第三方大模型厂商的请求体里。
你猜,合规部门看到这个请求体,会不会批?
下一集,PII 脱敏:敏感信息怎么在出门前被换成占位符,又怎么在回来之后分毫不差地填回去。
